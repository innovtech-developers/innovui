O InnovUI tem dois pacotes, com os mesmos componentes e o mesmo design system: `@innovui/react` para a web e `@innovui/react-native` para apps mobile. Escolha o seu (a escolha fica salva nas outras páginas).

Depois, importe o CSS da lib uma vez, no ponto de entrada da sua aplicação:

```tsx
import '@innovui/react/styles.css'
```

- **Next.js (App Router):** importe no `app/layout.tsx`.
- **Vite / Create React App:** importe no `main.tsx` ou `index.tsx`.

E use os componentes normalmente:

```tsx
import { Button } from '@innovui/react'

export function Example() {
  return <Button>Salvar alterações</Button>
}
```

**Requisitos:** React 19 ou mais recente (`react` e `react-dom` como peer dependencies). Não é necessário ter Tailwind CSS instalado no seu projeto: o CSS da lib já vem compilado.

Detalhes sobre Tailwind v4 e Server Components estão [mais abaixo](#web-tailwind-v4-e-server-components).

O pacote usa o [Uniwind](https://docs.uniwind.dev) (Tailwind v4 para React Native) para os estilos. Em resumo, são quatro passos:

1. **Metro:** envolva a config com `withUniwindConfig` (precisa ser o wrapper mais externo).
2. **`global.css`:** importe o Tailwind, o Uniwind e os tokens do InnovUI, e aponte o `@source` para a lib.
3. **Importe o `global.css`** no componente `App` (não no `index.js`).
4. **Use os componentes.**

```tsx
import { Button } from '@innovui/react-native'

export function Example() {
  return <Button onPress={() => {}}>Salvar alterações</Button>
}
```

**Requisitos:** React 19, React Native 0.81 ou mais recente, Tailwind CSS v4 e Metro (Expo ou React Native puro).

O passo a passo completo, com os arquivos de configuração, está em [Instalação e configuração do React Native](/react-native/instalacao/). Os componentes mudam em alguns pontos em relação à web: veja [Diferenças em relação à web](/react-native/diferencas/).

## Web: Tailwind v4 e Server Components

Esta parte vale só para o `@innovui/react`.

### Com Tailwind v4

Se o seu projeto já usa o Tailwind v4, os dois convivem sem conflito: as classes da lib têm o prefixo `iu:` e os tokens do tema do Tailwind dela viram `--iu-*`, então mudar o `@theme` do seu projeto (`--spacing`, `--radius-*`, `--font-sans`, cores…) **não** altera os componentes.

Importe o CSS da lib **antes** do Tailwind, no seu CSS global:

```css
@import "@innovui/react/styles.css";
@import "tailwindcss";
```

Nessa ordem, as suas classes ganham quando você passa `className` a um componente para mudar algo que ele já define (ex.: `<Button className="h-20">`), e a fonte do seu projeto (`--font-sans`) é a que os componentes herdam. Se invertida, as classes da lib vencem os conflitos e a fonte dos componentes passa a ser a da própria lib. Classes que não conflitam (`mt-4`, `w-full`) funcionam em qualquer ordem.

Verificamos esse cenário com Vite e com Next.js 16 (Server Component), em Tailwind v4, com o `@theme` do consumidor sobrescrevendo espaçamento, raio, fonte, cinza e tamanho de texto: o estilo computado dos 23 componentes testados fica idêntico ao de um app sem Tailwind, exceto pela fonte herdada.

### Server Components

Todo componente interativo já tem a diretiva `"use client"`, então funciona normalmente dentro de Server Components do Next.js (App Router), sem configuração adicional.
